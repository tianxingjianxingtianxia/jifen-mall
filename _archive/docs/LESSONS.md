# 积分商城项目复盘

## 2026-05-16：前端验收盲区

### 发生了什么

整个项目按 3 个 Sprint 完成开发，65 个后端测试全部通过，E2E 验证 27/27 通过。但上线后发现前端大量功能未正确对接：

- 商品详情页兑换按钮弹"开发中敬请期待"（没调后端 API）
- 首页商品卡片缺少兑换按钮（PRD 明确要求）
- 管理后台订单 Tabs 状态值差 1（点击筛选无数据）
- 库存为 0 后商品未自动下架
- 省市区用三个输入框代替联动选择器

### 根因

**验收流程的缺口，不是技术问题。**

| 缺了什么 | 后果 |
|:---|---:|
| 只测了后端 API | 没发现前端功能未对接 |
| 只测了成功路径 | 没发现库存为 0 不下架 |
| 只测了返回数据 | 没发现前端渲染状态值差 1 |
| 没逐条对照 PRD 验收 | 8 项 PRD 功能有缺失但未被发现 |

### 矫正措施

每个 Sprint 交付前必须执行以下标准化验收流程：

**第一步：对照 PRD 功能列表逐条检查**
- 打开 PRD，逐条确认"这个功能用户能不能用"
- 不只看"后端有没有接口"，要看"前端页面上按钮能不能点"

**第二步：核心流程手动走一遍**
- 注册 → 签到 → 浏览商品 → 兑换 → 取消 → 管理员发货 → 确认收货
- 每个步骤验证：按钮 → API 调用 → 页面跳转 → 数据刷新

**第三步：边界条件验证**
- 库存为 0 时能否兑换
- 积分不足时提示
- 重复签到拦截
- 订单状态每个 Tab 筛选

**第四步：门禁脚本**
- `e2e_verify.py` 作为必过门禁
- 不允许存在已知失败的测试项
