## 1. 微信一键登录 + 深度绑定

### 1.1 当前状态

**项目现状**：纯 PC Web 端（Vue3 + Vite + Element Plus + Spring Boot 3），没有任何微信生态代码。

**具体约束**：
- 前端使用 Vue3 + Vite，框架层面**无法直接运行于微信小程序环境**
- 小程序要求使用官方规定的标签语言（WXML/WXSS），不兼容 DOM 操作
- 用户表 `wj_user` 没有 `openid` / `unionid` 字段
- 没有微信开放平台账号及应用配置

### 1.2 技术方案

│  │ uni-app / Taro    │             │ Vue3 + Vite          │     │
│  │                  │    共享      │                      │     │
│  │ 微信登录组件      │ ◄─────────► │ 账号密码登录         │     │
│  │ 商品展示/兑换     │   同一后端    │ 订单管理             │     │

#### 前端（小程序端 — 新建项目）

| 方案 | 说明 | 优缺点 |
|:---|:---|:---|
| **方案 A：uni-app（推荐）** | 一套代码编译到 H5 + 小程序 | ★ 学习成本低、社区成熟；☆ 编译产物略大 |
| **方案 B：原生小程序** | 微信开发者工具原生开发 | ★ 性能最优；☆ 代码无法复用 Web 端 |
| **方案 C：Taro** | React 语法编译到多端 | ★ 跨端能力强；☆ 团队需 React 基础 |

**推荐方案 A：uni-app**，原因：
- 本团队现用 Vue3，uni-app 基于 Vue，迁移成本最低
- 现有 Element Plus 组件部分可替换为 uni-ui
- 可保留 PC Web 端，微信小程序作为独立入口并行存在

#### 后端（Spring Boot — 现有项目修改）

**新增接口**：
```
POST /auth/wechat-login
  请求: { "code": "wx_login_code" }
  响应: { "token": "jwt...", "user": {...} }

POST /auth/bind-wechat
  请求: { "code": "wx_bind_code", "userId": 123 }
  响应: { "openid": "xxx" }

GET  /auth/wechat-bound-info
  响应: { "bound": true, "openid": "xxx" }
```

**数据处理流程**：
1. 小程序端调用 `wx.login()` 获取临时 code
2. 后端用 code 请求微信接口获取 `openId` + `sessionKey`
3. 首次：自动注册新用户，绑定 openId
4. 已绑定：根据 openId 查到 userId，签发 JWT（等同于登录）
5. 深度绑定（已有账号）：先普通登录，再调 bind 接口关联 openId

#### 方案对比

| 方案 | 费用 | 特点 | 推荐 |
|:---|:---|:---|:---:|
| **快递100** | 免费版 500次/天 | 文档友好，接入简单 | ★ 推荐 |
| **快递鸟** | 免费版 1000次/月 | 支持更多快递公司 | 备选 |
| **快递网** | 免费版 1000次/天 | 实时查询 | 可考虑 |

**推荐快递100**，原因：
- 免费额度足够（积分商城日活低，500次/天足够）
- 接入最快（2 个 HTTP 接口即可）
- 提供订阅推送（发货后自动推送轨迹到你的回调地址）

#### 数据库变更

    KEY idx_tracking_no (tracking_no),

**实现策略**：
1. **首次查询**：请求快递100 API，获取完整轨迹，存入 `wj_logistics_record.data_json`
2. **缓存查询**：30 分钟内同一订单命中缓存不重复调 API（节省免费额度）
3. **订阅推送**：发货时调用快递100 订阅接口，物流更新时主动推送到后端回调地址
4. **到期清理**：签收后 7 天或创建后 90 天标记过期，不再查询
