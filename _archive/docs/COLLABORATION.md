# 积分商城 — 协作规范

## 一、文档优先原则

**开工前先出文档，再写代码。**

| 阶段 | 必出文档 | 给谁看 |
|:---|---|:---|
| Sprint 启动 | API 接口定义（字段+枚举值） | 前端/后端 |
| Sprint 启动 | 前端状态定义（Tab值/按钮条件） | 前端 |
| Sprint 启动 | 数据模型（表结构+字段说明） | 后端 |
| 交付前 | 验收结果（逐条对照 PRD） | 项目经理 |

**规则**：文档不输出，不进入编码阶段。项目经理没确认文档，不写一行代码。

---

## 二、API 字段定义规范

### 字段定义在哪里找

所有字段定义和枚举值统一写在 `docs/API.md` 中。每次新增/修改接口，必须同步更新该文档。

### 枚举值必须注明取值范围

```markdown
| 字段 | 枚举值 |
|:---|:---|
| 订单状态 status | 0=待发货 1=已发货 2=已完成 3=已取消 |
```

不要在代码里写 magic number。前端通过文档知道每个值的含义。

### 接口变更流程

```
需要改接口 → 先更新 docs/API.md → 通知协作方 → 再改代码
```

**禁止**：直接改代码再补文档。
**红线**：改完代码后，文档和代码不一致 = 没改完。

---

## 三、前后端对接检查

### 数据模型一致性

每条 SQL 建表语句、每个 Entity 类、每个 VO/DTO 写完**必须逐字段对照文档检查**：

```
SQL列名  ===  数据模型文档列名
Entity字段 ===  SQL列名
VO/DTO字段 ===  API文档字段
```

发现不一致当场改，不留到审核阶段。

### 前端取数路径

前端必须知道后端返回的 JSON 结构，包括：
- 分页数据在 `records` 还是 `list`
- 响应解包到哪一层
- 枚举值用 string 还是 number

统一规则：
```
成功响应: { code: 200, message: "success", data: {...} }
分页响应: data: { records: [...], total, pageNum, pageSize, pages }
枚举值: 统一用 number（Integer）
```

## 四、验收标准

### 验收标准什么时候定

**Sprint 启动时**，由项目负责人（Hermes）输出验收标准清单，项目经理确认后再开发。

### 验收标准包含什么

```
1. 功能清单（对照 PRD 逐条）
2. 业务规则（每条规则的验证场景）
3. 边界条件（积分不足/重复签到/库存为0/30天限制等）
4. 操作路径（按钮→API→跳转→数据刷新，每一步都要验证）
```

### 交付前必须执行

1. **后端自动化测试**：`mvn test` 全部通过
2. **E2E 测试**：`python3 e2e_verify.py` 全部通过
3. **前端交互验证**：打开浏览器，按验收清单逐条操作
4. **截图存档**：核心流程截图保存到 `docs/验收截图/`

**门禁规则**：以上四项有一项不通过，不能交付。

## 五、文档与代码一致性

### 改代码必须同时改文档

```
改代码 → 立即更新 docs/ 下对应文档 → 提交时包含文档变更
```

如果一次提交只有代码变更没有文档变更，**视为提交不完整**。

### 文档落后于代码怎么办

发现文档和代码不一致时：
1. 停下来
2. 以代码为准更新文档
3. 确认更新后的文档覆盖了所有变更
4. 再继续开发

**不能**先改代码再"回头补文档"——回头补的文档一定漏东西。

## 六、角色分工

| 角色 | 职责 | 不做的事 |
|:---|:---|---:|
| 项目经理（甲方） | 提需求、确认方案、最终验收 | 不干预日常执行、不当测试员 |
| 项目负责人（Hermes） | 输出文档、把控进度、内部审核、对甲方负责 | 不跳过文档环节、不交付未经测试的代码 |
| 子代理（Claude Code 等） | 编写代码、编写测试 | 不自行探索项目结构、不直接操作数据库 |

### 找甲方的场景

- 需求不明确需要决策
- 文档/方案需要确认
- 关键里程碑需要验收

### 不找甲方的场景

- 日常编码
- 内部测试
- Bug 修复

## 七、检查清单（交付前自检）

每次交付给项目经理前，逐条自检：

- [ ] API 文档已更新（docs/API.md）
- [ ] 验收标准已逐条验证（docs/验收标准.md）
- [ ] 后端测试全部通过（mvn test）
- [ ] E2E 测试全部通过（python3 e2e_verify.py）
- [ ] 核心交互流程已在浏览器走通
- [ ] 所有枚举值前后端一致
- [ ] 代码已提交且文档同步提交
