# 积分商城系统 PRD（PC Web 版）

## 一、需求背景
现有用户系统缺乏积分激励，需要积分商城提升用户活跃度。

## 二、用户故事

### 2.1 作为普通用户
- 我每天可以签到一次，获得积分
- 我可以查看我的积分余额和积分明细
- 我可以浏览可兑换的商品列表
- 我可以按价格排序、按名称搜索商品
- 我可以查看商品详情
- 积分足够时，我可以兑换商品
- 同一商品 30 天内只能兑换一次
- 兑换时需要选择收货地址
- 兑换成功后，积分即时扣除
- 我可以在“我的订单”中查看订单状态
- 订单 15 分钟内可以取消，取消后积分退回
- 我可以管理我的收货地址（增删改查、设默认）

### 2.2 作为运营人员
- 我可以上架/下架商品
- 我可以新增/编辑/删除商品
- 商品信息包含：名称、图片、所需积分、库存、描述
- 我可以查看所有订单
- 我可以将订单标记为“已发货”，并填写物流单号
- 我可以配置签到奖励的积分数量
- 我可以配置消费兑换比例（如 100 元 = 5 积分）
- 我可以查看兑换数据统计（热门商品、兑换趋势）

### 2.3 作为系统
- 兑换时库存为 0 的商品不能兑换
- 多人同时兑换最后一件商品时，只有一个人能成功
- 订单 15 分钟未处理，自动取消并退回积分
- 每年 12 月 31 日，当年获得的积分自动过期清零

## 三、功能列表

| 兑换订单 | 创建兑换订单 | P0 |

| 兑换订单 | 订单详情 | P0 |

## 四、页面结构（线框图描述）

### 4.1 积分商城首页
- 顶部导航栏：Logo、积分商城、我的订单、积分明细、用户名下拉菜单、退出
- 积分信息卡片区：显示可用积分、累计获得、累计兑换 + 签到按钮
- 商品搜索栏：搜索框、搜索按钮、排序下拉（按积分升序/降序）
- 商品网格区：4 列网格，每个卡片包含图片、名称、所需积分、兑换按钮
- 分页组件：上一页、页码、下一页

### 4.2 商品详情页
- 左侧：商品大图
- 右侧：商品名称、所需积分、库存状态、商品描述
- 收货地址：下拉选择已保存的地址，或“新增地址”链接
- 兑换按钮：点击后弹窗确认，确认后生成订单跳转到订单详情

### 4.3 我的订单页
- 状态筛选 Tab：全部、待发货、已发货、已完成、已取消
- 订单列表：每个订单展示商品图片、名称、所需积分、状态、操作按钮
- 操作按钮：待发货状态显示“取消订单”，已发货状态显示“确认收货”

### 4.4 地址管理页
- 地址列表：每个地址显示收货人、手机号、完整地址、默认标签
- 操作按钮：设为默认、编辑、删除
- 新增地址按钮：打开表单弹窗（收货人、手机号、省市区三级联动、详细地址）

### 4.5 管理后台 - 商品管理
- 商品列表表格：图片、名称、所需积分、库存、状态、操作
- 操作：新增、编辑、上下架、删除
- 新增/编辑表单：名称、图片上传、所需积分、库存、描述

### 4.6 管理后台 - 订单管理
- 订单列表表格：订单号、用户、商品、积分、状态、物流单号、操作
- 操作：待发货状态显示“发货”按钮，点击后弹出填写物流单号弹窗

## 五、业务规则

| 规则 | 说明 |
|:---|:---|
| 签到规则 | 每天 0 点重置，每人每天只能签到 1 次，奖励固定积分（可配置） |
| 兑换限制 | 同一用户对同一商品，30 天内只能兑换 1 次（以订单创建时间计） |
| 库存预扣 | 用户点击兑换后，库存预扣 15 分钟，超时未完成则释放 |
| 积分过期 | 每年 12 月 31 日 23:59:59，清理当年获得的积分 |
| 并发控制 | 最后一件商品多人同时兑换，只有 1 人能成功 |

## 六、验收标准（业务视角）

| 场景 | 预期结果 |
|:---|:---|
| 用户每天第一次签到 | 积分 +10，提示签到成功 |
| 用户同一天再次点击签到 | 提示“今日已签到”，积分不变 |
| 用户积分不足时兑换 | 提示“积分不足”，不扣库存 |
| 用户 30 天内重复兑换同一商品 | 提示“30天内只能兑换一次”，不扣积分 |
| 用户兑换最后一件商品 | 兑换成功，商品库存变为 0，自动下架 |
| 多人同时兑换最后一件商品 | 只有 1 人成功，其他人提示“库存不足” |
| 用户在 15 分钟内取消订单 | 订单取消，积分退回，库存恢复 |
| 用户 15 分钟未完成兑换 | 订单自动取消，积分退回，库存恢复 |
| 运营后台修改签到积分规则 | 次日签到按新规则发放 |
| 次年 1 月 1 日 | 用户积分正确扣除去年获得的积分 |

## 七、开发周期

3 个 Sprint，每个 Sprint 2 周：

- **Sprint 1**：积分中心 + 商品列表/详情 + 地址管理
- **Sprint 2**：兑换订单 + 取消订单 + 订单列表
- **Sprint 3**：管理后台全部功能 + 积分过期定时任务 + 并发处理
