## 二、业务规则验收

| # | 规则 | 验收要点 | 通过 | 备注 |
|:---|:---|---:|:---:|:---|
| R1 | 签到规则 | 每天0点重置，每人每天只能签到1次，奖励积分数可从配置读取（默认10） | ☐ | |
| R2 | 兑换限制 | 同一用户对同一商品，30天内只能兑换1次（以订单创建时间计，已取消的订单不计入） | ☐ | |
| R3 | 库存预扣 | 用户点击兑换后扣减库存，15分钟内未完成（取消/超时）则释放库存 | ☐ | |
| R4 | 积分过期 | 每年12月31日23:59:59清理当年获得的积分 | ☐ | |
| R5 | 并发控制 | 最后一件商品多人同时兑换，仅1人能成功 | ☐ | |
| R6 | 积分扣除 | 兑换时积分即时扣除，不可透支 | ☐ | |
| R7 | 取消时限 | 订单创建后15分钟内可主动取消，超时不可取消 | ☐ | |
| R8 | 库存为0自动下架 | 商品库存变为0时，前端页面应不再展示"兑换"入口 | ☐ | |

## 三、验收标准十条场景（PRD 第六节）

| # | 场景 | 前置条件 | 操作步骤 | 预期结果 | 通过 | 备注 |
|:---|:---|---:|:---|---:|:---:|:---|
| S1 | 用户每天第一次签到 | 用户当天未签到 | 调用签到接口 | 积分 +10，返回 todaySigned=true，points=奖励值 | ☐ | |
| S2 | 用户同一天再次点击签到 | 已签到 | 再次调用签到接口 | 提示"今日已签到"，积分不变，返回业务错误 | ☐ | |
| S3 | 用户积分不足时兑换 | 用户积分 < 商品所需积分 | 调用创建订单接口 | 提示"积分不足"，不扣库存，不消耗积分 | ☐ | |
| S4 | 30天内重复兑换同一商品 | 30天内已成功兑换过同一商品（已取消的除外） | 再次调用创建订单接口 | 提示"同一商品30天内只能兑换1次"，不扣积分 | ☐ | |
| S5 | 用户兑换最后一件商品 | 商品库存=1 | 调用创建订单接口 | 兑换成功，库存变0，前端应不再展示兑换入口或提示已售罄 | ☐ | |
| S6 | 多人同时兑换最后一件商品 | 商品库存=1，100并发 | 并发调用创建订单接口 | 仅1人成功，其余人提示"商品库存不足" | ☐ | |
| S7 | 15分钟内取消订单 | 订单状态=待发货，创建时间<15分钟 | 调用取消接口 | 订单状态变已取消，积分退回，库存恢复 | ☐ | |
| S8 | 15分钟未完成兑换 | 订单状态=待发货，创建超过15分钟 | 等待超时任务执行 | 订单自动取消，积分退回，库存恢复 | ☐ | |
| S9 | 运营后台修改签到积分规则 | 管理员已登录 | 修改 sign_in_points 配置值 | 次日签到按新规则发放积分 | ☐ | |
| S10 | 跨年积分过期 | 用户有当年获得的积分 | 12月31日23:59:59后检查 | 当年获得的积分被扣除，往年的不受影响 | ☐ | |

## 七、验收执行流程

每个 Sprint 交付前必须执行以下步骤：

1. **对照 PRD 功能列表逐条检查** — 打开 PRD，逐条确认"这个功能用户能不能用"
2. **核心流程手动走一遍** — 注册 → 签到 → 浏览商品 → 兑换 → 取消 → 管理员发货 → 确认收货，每个步骤验证按钮→API→页面跳转→数据刷新
3. **边界条件验证** — 按第四章节边界条件逐条验证
4. **门禁脚本** — 运行 `e2e_verify.py`（项目根目录），不允许存在已知失败的测试项
